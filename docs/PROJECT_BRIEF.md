# ledger-lite 프로젝트 개발 브리프 (최종본)

> Claude Code CLI에 그대로 전달하여 개발을 시작하기 위한 요구사항 정리 문서입니다.
> GitHub repo: `2026_ledger_lite`

---

## 1. 프로젝트 개요

**목적**: 은퇴(2026.7 퇴직) 후 생활비 소비를 촬영/입력만 하면 AI가 자동 분류·분석해주는
1인용 모바일 우선 AI 가계부 MVP.

**핵심 가치**: 찍고 → AI가 읽고 → 자동 분류 → 대시보드로 확인 → 카카오톡으로 리포트 받기

**스코프 원칙**:
- 연금(IRP/연저)·투자(종합계좌) 관련 데이터/분석은 **명시적으로 제외**
  (해당 내용은 별도 채팅/마스터 엑셀+CLI로 관리 중이며, 나중에 투자가 완결되면 별도 프로젝트로 분리)
- ledger-lite는 **순수 생활비 소비 관리**만 담당
- 연금 인출액이 입금되는 경우, "출처 분석 없이 금액만 수입으로 기록"하는 정도로만 취급

## 3. 기술 스택 (확정)

| 영역 | 선택 | 비고 |
|---|---|---|
| 프론트엔드 | **Streamlit** | 빠른 완성, 대시보드/차트 최적화 |
| OCR + AI 분류 | **Claude API 단일 통합** | Vision으로 영수증 이미지 직접 해석 + 카테고리 분류를 한 번의 호출로 처리 |
| DB | **로컬 SQLite** | 1인 사용, 소규모 데이터. 추후 필요 시 Supabase 전환 가능하도록 추상화 레이어 고려 |
| 차트 | Plotly | |
| 알림 | 카카오 메시지 API (나에게 보내기) | `POST /v2/api/talk/memo/default/send`, 별도 사용권한 신청 불필요 |
| 배포 | 우선 로컬 실행 → 안정화 후 Streamlit Community Cloud | 폰 접속용 |

## 4. 데이터 입력 채널 (확정: 3가지 소스, 처리방식 상이)

| 채널 | 샘플 포맷 | 처리 방식 |
|---|---|---|
| **카드 승인 문자** | `[Web발신] 현대카드M 승인 정*구 100,000원 일시불 08/08 09:48 대신주유소 누적669,523원` | 텍스트 붙여넣기 → 자동 파싱 (가맹점명 기반 AI 분류) |
| **카카오페이 송금(1/N)** | `[대화방이름] 6,800원을 보냈어요/받았어요.` | 텍스트 붙여넣기 → 자동 파싱, 카테고리는 **"라이프스타일비 > 소셜/네트워킹"**으로 기본 배정 |
| **실물 영수증 촬영** | 이미지 업로드 | Claude Vision으로 OCR+분류 |
| **은행 계좌이체/출금** | (구독료, 통신비, 연금, 보험료 등) | **수동 입력** — 적요만으로 자동분류 어려움, 사용자가 직접 카테고리 지정 |

**제외**: 카드사 CSV 다운로드, 이메일(Gmail) 연동

## 5. 계정과목 체계 (최종 확정)

### 지출 카테고리

| 대분류 | 소분류 |
|---|---|
| **고정비** | 관리비·공과금, 통신비, 보험료, 연금성 지출, 구독서비스 |
| **변동비** | 식비(외식·배달), 마트·생필품, 교통·주유, 의료·건강, 미용 |
| **라이프스타일비** | 테니스, 러닝·트레킹, 취미·여가, 도서·자기계발, **소셜/네트워킹**(카카오페이 송금·정산 전용) |
| **가족·경조사비** | 가족모임·외식, 경조사(축의금·부의금), 자녀지원, 부모님지원 |
| **비정기 대형지출** | 가전·전자기기, 여행, 고액의료비 |
| **(시스템 상태값)** | 미분류·확인필요 (카테고리 아님, 신뢰도 낮은 항목의 기본 상태) |

### 수입 카테고리 (단순화)
- 연금 인출액 유입 (금액만 기록, 출처 분석 없음)
- 기타 수입

## 6. 개발 원칙 (CLI 작업 시 준수)

- API 키는 코드에 하드코딩하지 않고 `.env` / 환경변수로만 관리
- 키가 없어도 로컬 모드(더미 데이터/스텁)로 전체 흐름 테스트 가능하도록 설계
- 수집(Collector)과 분석(Analyzer) 로직을 분리 — 원본 데이터/OCR 결과/분류 결과를 각각 다른 테이블에 저장
- 사용자가 카테고리를 수정하면 학습되어 다음 분류에 반영되는 구조 고려 (`merchant_rules` 방식)
- 카카오페이 송금은 상대방이 "사람 이름"이라 가맹점 기반 분류 불가 → 소셜/네트워킹으로 고정 배정 후 필요시 사용자가 재분류
- 은행 이체 적요가 코드성(예: `메리츠07-092`)인 경우 자동분류 시도하지 않고 수동 입력 흐름으로 유도
- 커밋 단위는 단계별(1단계 완료 → 커밋, 2단계 완료 → 커밋)로 진행

## 8. 1단계 착수 지시 (Claude Code CLI에 바로 전달할 문장)

> docs/PROJECT_BRIEF.md와 tests/fixtures/ 안의 샘플 데이터를 읽고 ledger-lite 1단계(프로젝트 구조 & DB 스키마)를 시작해줘.
> Streamlit + 로컬 SQLite 기반이고, 지출 카테고리는 고정비/변동비/라이프스타일비/가족경조사비/비정기대형지출 5개 대분류(각 소분류 포함)로 설계해줘.
> 연금/투자 관련 테이블은 만들지 않고, 수입은 "연금인출유입"과 "기타수입" 2종만 단순 기록하는 구조로 해줘.
> DB 스키마는 수집(captures/ocr_results)과 분석(receipts/classifications) 테이블을 분리해서 설계해줘.
> 카드문자, 카카오페이 송금, 영수증 이미지는 자동 파싱/분류 대상이고, 은행이체는 수동입력 전용으로 설계해줘.
